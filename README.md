# 4ブロック大会ボード — オフライン版（PWA）

iPad にインストールして、通信を切った状態で大会を進行できる Web アプリです。
Claude へのログインは不要です。

## 入っているファイル

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体（これ1つで全機能が動く） |
| `sw.js` | オフライン動作のための Service Worker |
| `manifest.json` | ホーム画面アプリとしての設定 |
| `icon-192.png` / `icon-512.png` | ホーム画面・アプリ一覧用アイコン |
| `apple-touch-icon.png` | iPad のホーム画面アイコン |
| `logo.jpg` | 「ツバサ ありがと会」の丸いロゴ画像（表紙とヘッダーに表示） |

これらのファイルは**同じフォルダに並べて置く**必要があります。`logo.jpg` が無い場合、ロゴの表示枠は自動的に消えます（他の機能は動きます）。

## 設置手順（GitHub Pages の場合）

Service Worker は `https://` でないと動かないため、HTTPS で配信できる場所に置きます。
GitHub Pages は無料で条件を満たします。

1. GitHub にログインし、**New repository** で新しいリポジトリを作る
   - 名前は任意（例：`taikai-board`）
   - **Public** を選ぶ（Private だと Pages が使えないプランがある）
2. **uploading an existing file** をクリックし、上記6ファイル（README.md は任意）をドラッグして **Commit changes**
3. リポジトリの **Settings** → 左メニューの **Pages** を開く
4. **Source** を `Deploy from a branch`、**Branch** を `main` / `/ (root)` にして **Save**
5. 1〜2分待つと、Pages の画面に公開URLが表示される
   `https://<ユーザー名>.github.io/taikai-board/`

このURLを iPad で開けば準備完了です。

> 自分の Web サーバーがあるなら、同じフォルダを HTTPS で配信するだけでも同じことができます。

## iPad 側の準備（当日より前に、通信できる場所で）

1. Safari で公開URLを開く
2. 何か操作して、画面が正しく表示されることを確認する
3. 共有ボタン（□に↑）→ **ホーム画面に追加** → 名前を確認して **追加**
4. **いったん Safari を閉じ、ホーム画面のアイコンから起動する**
   （この起動でオフライン用のキャッシュが確定します）
5. iPad を**機内モード**にして、もう一度アイコンから起動する
6. 起動できて、右上に「オフライン」と表示されれば成功

手順5〜6で起動できない場合は、機内モードを解除して 1〜4 をもう一度行ってください。

### 当日に他の人が iPad を触る場合

iOS の**アクセスガイド**を使うと、このアプリから抜け出せないように iPad をロックできます。

- 事前に「設定」→「アクセシビリティ」→「アクセスガイド」をオンにし、パスコードを設定
- アプリを起動した状態でトップボタンを3回押す → 「開始」
- 終了するときはトップボタンを3回押してパスコードを入力

これで、勝手に他のアプリを開かれたり設定を変えられる心配がなくなります。

## データについて

- 入力内容は iPad のブラウザ内に自動保存されます。アプリを閉じても消えません
- ただし Safari の「履歴とWebサイトデータを消去」を実行すると失われます
- 画面右上の **⤓ データ** から、進行状況を JSON ファイルに書き出せます。
  予選終了時など区切りごとに書き出しておくと、万一のときに復元できます
- 書き出したファイルは同じ画面の **⤒ ファイルから読み込む** で復元できます。
  別の iPad やパソコンへの引き継ぎにも使えます

## アプリを更新するとき

`index.html` を差し替えるだけでは、キャッシュが残っていて古い画面が表示されることがあります。
必ず `sw.js` の1行目付近にあるキャッシュ名の数字を上げてください。

```js
const CACHE = "block4-board-v5";   //  ← v6, v7 … と上げる
```

これで次回の起動時に古いキャッシュが破棄され、新しいアプリが読み込まれます。

## チーム登録の進め方（トランプ方式）

### 前日まで

1. おおよその参加人数から、**1チームの人数（3人 or 4人）** と **想定チーム数** を決める
2. アプリの「大会の設定」でその2つを選ぶ。必要人数が表示されるので確認する
3. 必要枚数のトランプを用意する
   - 1チーム3名 → **クローバーを抜く**（スペード・ダイヤ・ハートのみ）
   - 想定チーム数が10 → **J・Q・K を抜く**（1〜10だけ残す）
   - 想定チーム数が16 → **14〜16のカードを手作りする**

### 当日

4. 参加者は到着順にトランプを1枚引く。同じ数字の人が同じチーム
5. 引いてもらったら、アプリの「ニックネームの入力」でそのマークと数字のマスにニックネームを入力する
6. 同じ数字のニックネームが **スペード / クローバー / ダイヤ / ハート の順に「/」でつながって**チーム名になり、自動で登録される
7. 全員分そろったら「シャッフルして予選を組む」

### 人数が想定とずれたとき

- **少なかった**（1チーム分の人が来なかった）
  → その数字のマスを空のままにしておく。空の行はチームとして登録されない
- **多かった**（急に1チーム増えた）
  → 「追加チーム」の **＋ チームを追加** でチーム名を直接入力する。
  もしくは「想定チーム数」を増やしてカードの行を足してもよい
- どちらの場合も、**合計16チームまで**

## 大会ルール（アプリの動作）

- 予選：8〜16チームを4ブロックに均等配分し、ブロック内総当たり
  （13チームなら 4/3/3/3、16チームなら 4/4/4/4）
- 引き分けなし。同点スコアは入力エラーになる
- 順位：勝ち数 → 得失点差 → 直接対決の結果
- 3チーム以上が勝ち数・得失点差で並び、かつ直接対決が一巡している場合のみ、1位を手動で指定する
- 各ブロック1位の4チームを抽選し、準決勝・決勝を行う
- スコアは0〜999まで入力可能
- **▣ 大画面表示**：入力欄を隠し、星取表4つだけを拡大表示（HDMI / AirPlay でモニターに出す用）
- **◎ 表紙**：ロゴ画像を大きく投影する画面。大会前後の待ち時間用。もう一度押すと元の画面に戻る
